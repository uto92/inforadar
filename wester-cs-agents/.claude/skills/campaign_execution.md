# キャンペーン実行マニュアル
## WESTERエージェントシステム キャンペーンライフサイクル管理規範

**文書種別**: スキルマニュアル（新入担当者研修用）
**対象**: キャンペーン企画・実行・評価に関わるすべてのエージェント・担当者
**最終更新**: 2026年3月
**管理責任**: WESTERキャンペーン管理チーム

---

## はじめに

本マニュアルは、WESTERキャンペーンの企画から終了・振り返りまでの全工程を標準化するために作成されました。キャンペーンの品質・効果・安全性を担保するために、本マニュアルに記載されたすべてのチェックリスト・テンプレートを必ず使用してください。

キャンペーンは「思いつき」で動かしてはなりません。すべての施策は目的と根拠を持ち、会員・パートナー・社会に対して責任ある形で実施されなければなりません。ひとつのキャンペーンの失敗はWESTERブランド全体の信頼を傷つけます。本マニュアルをチームの共通言語として徹底活用してください。

## 1. キャンペーン種別一覧

WESTERが実施するキャンペーンは以下の種別に分類されます。それぞれ設計上の留意点が異なるため、種別の正確な識別が重要です。

### 1-1. スタンプラリー型

**概要**: 対象スポット（駅・店舗・観光地等）を訪問してスタンプを集め、達成数に応じた特典を付与するキャンペーン。

**特徴**:
- 会員の移動・訪問行動を直接促進できる
- JR西日本の沿線活性化・地域まちづくりとの親和性が高い
- スポット設計・システム連携・運用期間管理が複雑になりやすい
- 参加ハードルの設計（達成数の設定）が参加率に大きく影響する

**代表例**: 春の西日本スタンプラリー、沿線グルメスタンプラリー、新幹線開通記念スタンプラリー

### 1-2. ポイント還元型

**概要**: 特定の行動（乗車・購買・アプリ操作等）に対して通常より多くのWESTERポイントを付与するキャンペーン。

**特徴**:
- 設計・告知が比較的シンプル
- ポイントコストの試算が重要（付与ポイント数×参加者数の上限設定）
- 会員の既存行動に対する「追加報酬」なので参加ハードルが低い
- 会員の行動変容につながりにくい（もともとやる行動に対する付与のため）

**代表例**: 乗車ポイント2倍キャンペーン、アプリログインポイント付与、誕生月ポイントアップ

### 1-3. 期間限定特典型

**概要**: 一定期間内に特定の条件を満たした会員に、クーポン・割引券・限定グッズ等を付与するキャンペーン。

**特徴**:
- 「今しか手に入らない」緊急性が参加動機を高める
- 在庫管理・数量制限の設計が重要
- 特典の魅力度がキャンペーン成否に直結する
- 景品表示法等の法的制約を必ず確認する

**代表例**: 夏の旅行クーポンプレゼント、先着1,000名への限定グッズ配布、誕生月割引クーポン

### 1-4. 会員獲得型

**概要**: 新規会員の獲得を主目的とした紹介プログラム・入会特典キャンペーン。

**特徴**:
- 既存会員への紹介インセンティブ設計が重要
- 入会後の定着率（継続利用率）も同時にモニタリングする
- 対象条件（例：初めてWESTERに登録する方）の定義を厳密にする

**代表例**: 友だち紹介キャンペーン、入会ポイント付与、JR西日本ご利用者向け特別入会特典

### 1-5. パートナー連携型

**概要**: 沿線の商業施設・飲食店・観光施設等のパートナー企業と共同で実施するキャンペーン。

**特徴**:
- パートナー企業との合意形成・役割分担が事前に必要
- 告知媒体・費用分担の取り決めが必要
- パートナー企業の業務負担（システム改修・スタッフ研修等）を考慮した設計が必要

**代表例**: 駅ナカ商業施設ポイントアップ、沿線ホテル特別割引、観光協会連携スタンプラリー

### 1-6. 行動促進型（チャレンジ型）

**概要**: 会員に特定の行動目標（乗車回数・歩数・アプリ利用回数等）を設定し、達成状況に応じてポイントや特典を付与するキャンペーン。

**特徴**:
- ゲーミフィケーション要素が強く、エンゲージメント向上に有効
- 目標値の設定が会員にとって「達成感を感じられる程よい難易度」であることが重要
- 進捗の可視化（進捗バー・マイページ表示等）がシステムに必要

**代表例**: 月間10回乗車チャレンジ、WESTERアプリ連続ログインチャレンジ

### 1-7. 季節・記念日連動型

**概要**: 年末年始・ゴールデンウィーク・お盆・地域の祭り等の季節イベントや、JR西日本の記念日に合わせて実施するキャンペーン。

**特徴**:
- 毎年定例化しやすいが、マンネリ化に注意が必要
- 期間中のシステム負荷（アクセス集中）への対策が必要
- 前年との比較が容易で、効果測定がしやすい

## 2. 企画フェーズ チェックリスト

企画フェーズでは「このキャンペーンをなぜやるのか」「何を達成するのか」を明確にします。このフェーズが曖昧なまま次に進むと、後工程で手戻りが発生します。

### 2-1. 目的・課題設定

- [ ] 解決したい課題または達成したい目的を1〜2文で明文化したか
- [ ] その課題・目的がWESTERの中長期戦略（年間計画・KPI）に紐付いているか確認したか
- [ ] 課題の根拠となるデータ（会員数推移・利用頻度・競合分析等）を確認したか
- [ ] 他施策（過去のキャンペーン・進行中の施策）との重複・競合がないか確認したか

### 2-2. ターゲット設定

- [ ] 対象とする会員セグメントを明確に定義したか（年齢・居住エリア・利用頻度・会員ステージ等）
- [ ] ターゲット会員数（母集団）を把握したか
- [ ] ターゲット外の会員への影響・配慮を検討したか（例：参加できない会員への丁寧な説明）
- [ ] JR西日本コミュニケーションズとのデータ連携が必要な場合、承認プロセスを確認したか

### 2-3. 予算設定

- [ ] キャンペーンに使用可能な予算枠を確認したか（承認済み予算か）
- [ ] ポイント付与コスト（ポイント単価×想定付与数）を試算したか
- [ ] システム開発・改修コストを確認したか（IT部門へのヒアリング）
- [ ] 告知・広告コストを確認したか（メール配信・プッシュ通知・外部広告）
- [ ] 特典物（グッズ・クーポン等）の調達コストを確認したか
- [ ] 予備費として予算の10〜15%を確保したか
- [ ] 予算超過時の判断権限者を確認したか

### 2-4. KPI設定

- [ ] 主要KPI（Primary KPI）を1〜2個設定したか（例：参加者数・新規会員獲得数）
- [ ] 副次KPI（Secondary KPI）を3〜5個設定したか（例：ポイント獲得率・特典受取率・アプリ起動回数）
- [ ] 各KPIの目標値の根拠（過去実績・ベンチマーク等）を文書化したか
- [ ] KPIのモニタリング方法・データソースを確認したか
- [ ] キャンペーン終了後の効果測定方法（前後比較・コントロール群等）を決定したか

### 2-5. スケジュール設定

- [ ] 告知開始日・キャンペーン開始日・終了日・効果測定完了日を設定したか
- [ ] 逆算スケジュール（いつまでに何を完了すべきか）を作成したか
- [ ] 承認プロセス（社内稟議・コンプライアンス確認等）の所要時間を考慮したか
- [ ] 他のキャンペーン・会社イベントとの日程重複を確認したか

## 3. 設計フェーズ チェックリスト

設計フェーズでは「このキャンペーンをどのように動かすか」を詳細に決定します。設計の曖昧さは会員・パートナー・システムへの混乱を引き起こします。

### 3-1. キャンペーンルール設計

- [ ] 参加条件（誰が参加できるか）を明確かつ網羅的に記載したか
- [ ] 除外条件（参加できない会員・行動）を明確に定めたか
- [ ] 特典付与条件（何をすれば何が得られるか）を誰でも理解できる言葉で記載したか
- [ ] 特典付与のタイミング（即時付与か後日付与か）を決定したか
- [ ] ルール変更が発生した場合の対応方針を決定したか
- [ ] 不正参加（なりすまし・複数アカウント利用等）への対策を検討したか
- [ ] 弁護士・コンプライアンス担当によるルール確認を受けたか

### 3-2. 特典設計

- [ ] 特典の種類（ポイント・クーポン・グッズ・割引等）を決定したか
- [ ] 特典の付与数量・上限を設定したか（数量限定の場合は明確な数を設定）
- [ ] 特典の有効期限を設定したか
- [ ] 特典の調達・準備スケジュールを確認したか
- [ ] 景品表示法・消費税法等の法的制約を確認したか（懸賞・景品に該当する場合は特に注意）
- [ ] 特典の原価・調達先を確認・承認したか

### 3-3. システム要件確認

- [ ] キャンペーン実施に必要なシステム機能をIT部門と合意したか
- [ ] 新規開発・改修が必要な機能のスコープと所要期間を確認したか
- [ ] テスト環境での動作確認の計画を立てたか
- [ ] システム障害発生時の代替手段（手動対応の可否等）を確認したか
- [ ] キャンペーン期間中のシステム負荷（アクセス集中）への対策を確認したか
- [ ] データ取得・分析に必要な計測タグ・ログ設計が完了しているか

### 3-4. リスク検討

- [ ] 想定されるリスクを洗い出したか（技術・運用・法的・評判等）
- [ ] 各リスクに対する対応策（コンティンジェンシープラン）を用意したか
- [ ] キャンペーン中断・緊急停止が必要な場合の判断基準と権限者を定めたか
- [ ] リスク管理マトリクス（第8章参照）を作成したか

## 4. 実行フェーズ チェックリスト

実行フェーズでは「告知から終了まで、計画通り安全に運営する」ことが目標です。

### 4-1. 告知・配信

- [ ] 告知コンテンツ（メール・プッシュ通知・Web・SNS等）の最終確認を完了したか
- [ ] WESTERブランドガイドに沿った表現・デザインになっているか
- [ ] 対象会員セグメントへの配信設定を正確に行ったか
- [ ] 告知の法的確認（景品表示法・個人情報保護法等）は完了したか
- [ ] テスト配信（少数サンプルへの配信）で問題がないことを確認したか
- [ ] 全チャネルへの告知タイミングの整合性を確認したか（メールとWebの更新タイミング等）
- [ ] お問い合わせ対応体制（コールセンター・FAQ更新）が整っているか

### 4-2. 開始時確認

- [ ] キャンペーン開始時刻に合わせて全システムが正常に稼働していることを確認したか
- [ ] スタンプ・ポイント等の付与が正常に行われているかをテストしたか
- [ ] 会員からの初期反応（問い合わせ内容・SNSの反応）を確認したか
- [ ] 担当者全員がキャンペーン詳細（参加条件・特典・終了日等）を把握しているか

### 4-3. 進行中モニタリング

- [ ] 日次モニタリングの実施担当者・時刻を決定し、周知したか（モニタリング詳細は第5章参照）
- [ ] 参加者数・特典消化率・ポイント付与状況を毎日確認しているか
- [ ] システムアラート（エラー率・応答時間等）を監視しているか
- [ ] 会員からの問い合わせ内容を集計・分析し、FAQ更新等の対応を行っているか
- [ ] KPIが目標に対して乖離している場合の緊急対策を検討したか

### 4-4. トラブル対応

- [ ] トラブル発生時の連絡フロー（誰に・どの順番で・何を報告するか）を明確にしているか
- [ ] システム障害・ポイント二重付与・不正参加等の対応手順書を用意しているか
- [ ] 会員への影響が生じた場合のお詫び・補償方針を事前に決定しているか
- [ ] キャンペーン緊急停止の判断基準と操作手順を担当者全員が把握しているか

## 5. 終了フェーズ チェックリスト

### 5-1. キャンペーン終了処理

- [ ] 告知媒体すべてにキャンペーン終了の表示をしたか（Webページ・プッシュ通知等）
- [ ] 終了後も問い合わせに対応できる体制を一定期間（2週間程度）維持しているか
- [ ] 特典の付与処理が全件完了したことを確認したか
- [ ] 未付与・エラー件数を把握し、個別対応の要否を判断したか

### 5-2. 効果測定

- [ ] 設計フェーズで設定した全KPIの実績値を収集したか
- [ ] 主要KPIの目標対比（達成率）を算出したか
- [ ] 会員セグメント別の効果（参加率・特典利用率等）を分析したか
- [ ] コスト実績（ポイント付与コスト・システムコスト・運用コスト）を集計したか
- [ ] ROI（投資対効果）を算出したか

### 5-3. 報告

- [ ] 効果測定レポートを作成したか（フォーマットは第10章の内容に準ずる）
- [ ] 上長・経営層への報告タイミングと形式を確認したか
- [ ] JR西日本コミュニケーションズ等の連携先への報告を行ったか

### 5-4. 振り返り（レトロスペクティブ）

- [ ] 担当チーム全員参加の振り返り会議を開催したか
- [ ] 「よかった点」「改善すべき点」「次回への提案」を文書化したか
- [ ] 振り返り結果を次回の同種キャンペーン企画書のインプットに反映したか
- [ ] 成功事例・失敗事例をチーム内のナレッジとして共有・保存したか

【付与タイミング】
対象行動完了後、（即時 / 翌営業日 / ○日以内）にWESTERポイントとして付与します。
付与後、WESTERアプリの「ポイント明細」画面でご確認いただけます。

【付与遅延が生じる場合の対応】

```

**ポイント有効期限の設定**

※通常ポイントとは有効期限が異なります
```

**不正利用対策**

- [ ] 同一会員IDによる重複付与の防止ロジックを実装・確認したか
- [ ] 大量取得（閾値：〇ポイント以上の1日付与）のモニタリングアラートを設定したか
- [ ] 不正と判断された場合のポイント取り消し手順を確認したか
- [ ] 不正対応の判断権限者（承認者）を確認したか

## 8. リスク管理マトリクス

キャンペーン設計時に以下のリスク管理マトリクスを使用して、各リスクの優先度を評価し、対応策を準備してください。

### リスク評価方法

**発生確率レベル**:
- 高（3）：過去の同種キャンペーンで3回以上発生、または業界で一般的なリスク
- 中（2）：過去に1〜2回発生、または発生可能性がある
- 低（1）：発生事例なし、または可能性が非常に低い

**影響度レベル**:
- 大（3）：会員全体または大規模なシステムに影響。ブランド毀損リスクあり
- 中（2）：一部の会員または特定機能に影響。対応工数が大きい
- 小（1）：影響範囲が限定的。対応工数が小さい

**優先度スコア** = 発生確率 × 影響度（最大9、最小1）

### キャンペーン共通リスクマトリクス

| リスク | 発生確率 | 影響度 | スコア | 優先度 | 対応策 | 担当 |

## 9. よくあるミス・NG事例

過去の実施事例・ヒアリングをもとに、担当者が陥りやすいミスをまとめました。必ず目を通し、同じ失敗を繰り返さないようにしてください。

### NG事例1：参加条件の曖昧な設定

**状況**: 「JR西日本をご利用の方」と告知したが、「ICOCAポイント会員でないと参加できない」という追加条件を伝えておらず、会員から多数のクレームが来た。

**原因**: 参加条件の定義を「だいたいこういう人」と曖昧に設定し、レビューが不十分だったため。

**対策**: 参加条件は「条件を満たす人の具体例」と「除外される人の具体例」を両方列挙し、法務・担当責任者のダブルチェックを義務化する。

---

### NG事例2：システムテスト不足によるポイント二重付与

**状況**: スタンプラリーのQRコード読み取り後、通信エラーが発生した会員が再度読み取りを行い、スタンプが2つ取得できる状態になっていた。その結果、全達成条件を1スポットで満たす不正参加が続出した。

**原因**: エラー時の再試行ロジックのテストが不十分だった。

**対策**: テスト計画に「通信エラー・タイムアウト時の挙動」を必須項目として含める。負荷試験・異常系テストをリリース1週間前に完了する。

---

### NG事例3：告知のチャネル間でルールに矛盾が生じた

**状況**: メールには「4月30日終了」と記載し、Webページには「5月1日終了」と誤記されていた。会員からの指摘で発覚したが、対応に追われてブランドイメージが傷ついた。

**原因**: 各チャネルの告知原稿を別々の担当者が作成し、最終的な整合性チェックが行われていなかった。

**対策**: 全チャネル告知原稿の最終確認は、必ず1人の責任者がすべてを横断的に確認するプロセスを設ける。

---

### NG事例4：予算を超過したにもかかわらず報告が遅れた

**状況**: キャンペーン参加者数が想定の2倍に達し、ポイント付与コストが予算の150%を超えた。しかし担当者が「後で報告すればいい」と判断し、月次報告まで上長に伝えなかった。

**原因**: 予算超過時のエスカレーション基準と報告ルールが明確でなかった。

**対策**: 予算の80%消化時点で報告義務（アーリーアラート）、100%消化時点でエスカレーション義務（上長承認なしには継続不可）を明文化する。

---

### NG事例5：パートナー企業への事前ブリーフィング不足

**状況**: スタンプラリーのスポットとなった沿線飲食店に、会員から問い合わせが殺到した。飲食店スタッフはキャンペーン詳細を知らず、「そんなのやってないですよ」と回答してしまい、会員から怒りの声がWESTERに届いた。

**原因**: パートナー企業への告知が、キャンペーン開始の3日前に書面一枚で行われただけだった。

**対策**: パートナー企業へは開始2週間前にブリーフィング資料を送付し、1週間前にオンラインまたは対面での説明会を実施することを必須とする。担当者向けFAQも別途作成する。

---

### NG事例6：景品表示法の確認漏れ

**状況**: 「先着100名に○○プレゼント」と告知したが、特典の市場価格が景品表示法の懸賞景品の上限額を超えていたことが、社内の法務チェックで公開後に発覚した。急遽、告知の修正と会員への謝罪が必要になった。

**原因**: 企画担当者が法律の知識を持っておらず、設計段階で法務確認を省略した。

**対策**: 金銭的価値を持つ特典（クーポン・物品・旅行券等）を付与するキャンペーンは、必ず企画フェーズ段階で法務部門のレビューを受けることを必須工程とする。

---

### NG事例7：KPI目標の根拠なし設定

**状況**: 「参加者数の目標を10万人にしましょう」と決定したが、根拠は「なんとなく多そうな数字だから」だった。終了後、目標の40%しか達成できず、経営層からの信頼を損ねた。

**原因**: 過去実績・市場データを参照せずに目標を設定した。

**対策**: 目標値は必ず「過去の同種施策の実績値」「対象会員数に対する参加率の想定」「他社ベンチマーク」の3つのいずれかを根拠として文書化することを義務化する。

---

### NG事例8：「延長します」の判断が遅れ、会員が混乱

**状況**: 台風の影響でJR西日本の多くの路線が運休となり、スタンプラリーへの参加が困難になった。担当者は「延長すべきかどうか」を内部で検討し続け、判断が3日間遅れた。その間、会員から問い合わせが多数入り、SNS上でも不満の声が広がった。

**原因**: 緊急事態発生時の「キャンペーン延長・変更の判断基準と権限者」が事前に定まっていなかった。

**対策**: 設計フェーズで「緊急停止・変更の判断基準（例：JR西日本の主要路線が○路線以上で4時間以上の運休が発生した場合）」と「判断権限者（○○部長以上）」を事前に文書化する。

---

### NG事例9：終了後の特典付与処理忘れ

**状況**: キャンペーン終了後に「達成特典の付与が一部の会員にされていない」という問い合わせが多数来た。調査すると、終了処理のバッチ処理が一部失敗しており、担当者がモニタリングしていなかったことが原因だった。

**原因**: 終了フェーズのチェックリストが存在せず、処理完了確認が担当者任せになっていた。

**対策**: キャンペーン終了日の翌営業日を「完了確認日」として設定し、付与処理の完了確認・エラー件数の確認・個別対応の完了確認を義務付けるチェックリストを運用する。

---

### NG事例10：振り返りが省略され、同じミスを翌年も繰り返した

**状況**: 前年のスタンプラリーで「パートナー企業へのブリーフィング不足」の問題が発生したが、振り返りが実施されず、翌年も同じ問題が起きた。

**原因**: 「忙しいから」という理由で振り返り会議が省略された。

**対策**: 振り返り会議はキャンペーン終了から2週間以内に実施することを必須とし、実施報告書の提出を義務化する。未実施の場合、次のキャンペーンの承認が下りない仕組みにする。

## 10. JR西日本コミュニケーションズ連携時の確認事項

WESTERキャンペーンの多くにおいて、JR西日本コミュニケーションズ（以下、コミュニケーションズ）との連携が発生します。連携時には以下の事項を必ず事前に確認・合意してください。

### 10-1. 連携が必要な場面

- WESTERアプリのUI変更・新機能追加が伴うキャンペーン
- 会員へのメール配信・プッシュ通知の配信委託
- デジタル広告・SNS広告の出稿委託
- 外部向けWebページの制作・更新委託
- データ集計・効果測定の委託

### 10-2. 連携時の事前確認事項

**スケジュール関連**:
- [ ] コミュニケーションズへの依頼は開始日の（最低4週間前）に完了しているか
- [ ] コミュニケーションズ側のスケジュール（稼働状況・他案件との競合）を確認したか
- [ ] 修正・フィードバックのラウンド数と所要時間をスケジュールに組み込んでいるか

**費用・契約関連**:
- [ ] 依頼内容に対する見積もりを取得したか
- [ ] 予算内に収まることを確認したか（超過する場合は上長承認を得たか）
- [ ] 委託契約・発注書の締結が完了しているか（口頭発注は禁止）
- [ ] 成果物の権利帰属・利用範囲を契約書で合意しているか

**品質・確認関連**:
- [ ] 成果物の確認・承認フロー（誰が何を確認するか）を合意しているか
- [ ] WESTERブランドガイドをコミュニケーションズ担当者と共有しているか
- [ ] 最終成果物の品質基準（解像度・フォーマット・文字数等）を明示しているか

**連絡体制**:
- [ ] コミュニケーションズ側の担当者名・連絡先（電話・メール）を確認したか
- [ ] 緊急時の連絡方法（時間外対応の可否・エスカレーション先）を確認したか
- [ ] 定例連絡会議のスケジュールを設定したか（長期プロジェクトの場合）

### 10-3. 依頼書の記載必須項目

コミュニケーションズへの依頼は必ず依頼書（書面またはメール）で行います。依頼書には以下を必ず記載してください。

```
【依頼書 必須記載事項】

1. 依頼日
2. 依頼元（部署名・担当者名・連絡先）
3. 件名（キャンペーン名＋依頼内容の概要）
4. 依頼内容の詳細（何を・どのように・どの品質で作成してほしいか）
5. 成果物の形式・仕様（ファイル形式・サイズ・文字数等）
6. 参考資料（ブランドガイド・過去事例・ラフ案等）
7. 提出期限（YYYY年MM月DD日 HH時まで）
8. 確認担当者と承認プロセス
9. 予算（見積もり上限金額）
10. 発注番号（経理管理用）
```
