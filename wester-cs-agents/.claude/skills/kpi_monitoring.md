# KPIモニタリングマニュアル
## WESTERエージェントシステム KPI定義・計測・報告標準規範

**文書種別**: スキルマニュアル（新入担当者研修用）
**対象**: KPI設定・モニタリング・分析・報告に関わるすべてのエージェント・担当者
**最終更新**: 2026年3月
**管理責任**: WESTERデータ分析チーム

---

## はじめに

本マニュアルは、WESTERサービスに関わるKPI（重要業績評価指標）の定義・計測・モニタリング・報告を標準化するために作成されました。

「計測できないものは改善できない」という原則のもと、すべての施策・サービス運営はKPIによる客観的な評価に基づいて意思決定されなければなりません。本マニュアルに従って、正確・迅速・分かりやすいKPI管理を実践してください。

また、KPIは「数字を出すこと」が目的ではありません。数字の背景にある会員の行動・感情・文脈を理解し、次の意思決定に結びつけることが真の目的です。単なる数値報告者ではなく、データを通じてWESTERの成長に貢献する分析者であることを意識してください。

---

## 1. WESTER KPI体系

WESTERのKPIは以下の5つのカテゴリーに分類されます。各カテゴリーは相互に関連しており、単一のカテゴリーだけを見るのではなく、全体のバランスで状況を判断することが重要です。

### 1-1. 会員基盤KPI（Who）

会員基盤の規模と質を示す指標群です。

| KPI名 | 説明 | 重要度 |
|---|---|---|
| 累計会員数 | WESTERポイント会員として登録されている会員の総数 | ★★★ |
| 月間新規会員数 | 当月に新たにWESTER会員登録を完了した会員数 | ★★★ |
| 月間退会者数 | 当月に退会・アカウント削除を行った会員数 | ★★ |
| 純増会員数 | 月間新規会員数 − 月間退会者数 | ★★★ |
| アクティブ会員数 | 直近90日以内にWESTERアプリを起動またはポイントを獲得・利用した会員数 | ★★★ |
| 会員ステージ別構成比 | 各ステージ（グレード）の会員数の割合 | ★★ |
| 継続率（リテンション率） | 前月にアクティブだった会員のうち当月もアクティブな会員の割合 | ★★★ |
| チャーン率（離脱率） | 前月にアクティブだった会員のうち当月非アクティブになった会員の割合 | ★★★ |

### 1-2. 利用頻度KPI（How Often）

会員がどのくらいの頻度でWESTERサービスを利用しているかを示す指標群です。

| KPI名 | 説明 | 重要度 |
|---|---|---|
| 月間アプリ起動回数（会員平均） | アクティブ会員1人あたりの月間WESTERアプリ起動回数の平均値 | ★★★ |
| 月間乗車回数（会員平均） | WESTERポイントが付与された乗車のうち、アクティブ会員1人あたりの月間乗車回数平均 | ★★★ |
| 月間購買回数（加盟店）（会員平均） | パートナー加盟店での購買によりポイントが付与された月間購買回数の会員平均 | ★★ |
| DAU（日次アクティブユーザー数） | 当日WESTERアプリを1回以上起動した会員数 | ★★ |
| MAU（月次アクティブユーザー数） | 当月WESTERアプリを1回以上起動した会員数 | ★★★ |
| DAU/MAU比（スティッキネス） | DAU ÷ MAU。値が高いほど毎日利用されているサービスであることを示す | ★★ |

### 1-3. エンゲージメントKPI（How Deep）

会員がWESTERサービスにどの程度深く関与しているかを示す指標群です。

| KPI名 | 説明 | 重要度 |
|---|---|---|
| 機能利用率（主要機能別） | WESTERアプリの各機能（デジタル会員証・ポイント確認・乗車履歴等）を利用した会員の割合 | ★★ |
| キャンペーン参加率 | 対象会員数に対する実際のキャンペーン参加者数の割合 | ★★★ |
| 特典受取率 | キャンペーン参加者のうち特典を実際に受け取った会員の割合 | ★★ |
| プッシュ通知開封率 | 送信したプッシュ通知を開封した会員の割合 | ★★ |
| メール開封率 | 送信した会員向けメールを開封した会員の割合 | ★★ |
| メールCTR（クリック率） | メール開封者のうち本文内リンクをクリックした会員の割合 | ★★ |
| NPS（ネット・プロモーター・スコア） | 会員がWESTERを他者に推薦する意向の強さを示すスコア（−100〜+100） | ★★★ |

### 1-4. ポイント経済圏KPI（Value Flow）

WESTERポイントの流通・消費状況を示す指標群です。ポイントの健全な流通がサービスの財務的持続可能性に直結します。

| KPI名 | 説明 | 重要度 |
|---|---|---|
| 月間ポイント発行数 | 当月付与されたWESTERポイントの総数 | ★★★ |
| 月間ポイント消費数 | 当月利用（交換・使用）されたWESTERポイントの総数 | ★★★ |
| ポイント消費率 | 発行ポイントに対する消費ポイントの割合（月間または累計） | ★★★ |
| ポイント失効数 | 当月失効したWESTERポイントの総数 | ★★ |
| ポイント失効率 | 発行ポイントに対する失効ポイントの割合 | ★★ |
| ポイント残高合計 | 全会員が保有するWESTERポイントの総残高（財務上の負債として管理） | ★★★ |
| 会員平均保有ポイント | 全会員の保有ポイントの平均値 | ★★ |
| 交換先別消費内訳 | ポイントの交換・利用先（乗車券・クーポン・加盟店等）の構成比 | ★★ |

### 1-5. 事業成果KPI（Business Impact）

WESTERの事業・社会的貢献としての成果を示す指標群です。

| KPI名 | 説明 | 重要度 |
|---|---|---|
| WESTER経由の乗車促進数 | WESTERキャンペーン・特典を起点とした乗車増加数（前年比または対コントロール群比） | ★★★ |
| パートナー企業売上貢献額 | WESTERポイント利用による加盟店への推計売上貢献額 | ★★ |
| アプリDL数（累計） | WESTERアプリの累計ダウンロード数 | ★★★ |
| 施策ROI | キャンペーンにかけたコストに対して生み出した便益の比率 | ★★★ |

## 2. KPI定義標準

すべてのKPIは以下の「KPI定義シート」の形式で管理します。KPI定義シートが存在しないKPIをレポートに使用することは禁止します。新たなKPIを追加する場合は、必ず定義シートを作成してデータ分析チームリーダーの承認を得てください。

### 2-1. KPI定義シートの記載項目

| 項目 | 説明 |
|---|---|
| KPI名 | 正式名称（表記を統一する） |
| カテゴリー | 第1章の5カテゴリーのうちどれに属するか |
| 定義（日本語） | このKPIが何を計測するかを、計算式を使わずに平易な言葉で説明した文章 |
| 計算式 | KPIの値を導き出す計算式。使用する変数の定義も明記する |
| 計算例 | 具体的な数値を使った計算例 |
| データソース | 使用するデータが格納されているシステム・データベース名と対象テーブル・フィールド名 |
| 更新頻度 | 日次 / 週次 / 月次 / 四半期 のいずれか |
| 更新タイミング | 更新日の何時頃に最新データが反映されるか |
| データ欠損・異常値の扱い | データが欠損していた場合・明らかな異常値が検出された場合の処理方法 |
| 責任者 | このKPIの定義管理・値の正確性に責任を持つ担当者（部署名・氏名） |
| 最終更新日 | 定義が最後に更新された日付 |

### 2-2. 主要KPI定義シート（記載例）

---

**KPI定義シート: アクティブ会員数**

| 項目 | 内容 |
|---|---|
| KPI名 | アクティブ会員数 |
| カテゴリー | 会員基盤KPI |
| 定義 | 直近90日以内にWESTERアプリを1回以上起動、またはWESTERポイントを1ポイント以上獲得もしくは利用した会員の数。退会・アカウント停止中の会員は除外する。 |
| 計算式 | アクティブ会員数 = （集計日から90日以内にアプリ起動またはポイント取引が1件以上ある会員ID）のユニーク数 |
| 計算例 | 2026年3月1日時点のアクティブ会員数 = 2025年12月1日〜2026年3月1日の間にアプリ起動またはポイント取引があった会員IDのユニーク数 |
| データソース | WESTER会員DBの「member_activity」テーブル（last_app_open_date, last_point_transaction_date） |
| 更新頻度 | 日次 |
| 更新タイミング | 毎朝7時（前日23:59までのデータを集計） |
| データ欠損の扱い | last_app_open_dateとlast_point_transaction_dateのいずれか一方でも条件を満たせばアクティブとみなす。両フィールドがNULLの会員は非アクティブとみなす。 |
| 責任者 | データ分析チーム・〇〇（メール：xxx@xxx.jp） |
| 最終更新日 | 2026年1月15日 |

---

**KPI定義シート: ポイント消費率**

| 項目 | 内容 |
|---|---|
| KPI名 | ポイント消費率 |
| カテゴリー | ポイント経済圏KPI |
| 定義 | 対象期間（月間）に付与されたWESTERポイントのうち、同期間内に消費（利用・交換）されたポイントの割合。ポイントの流通健全性を示す指標。 |
| 計算式 | ポイント消費率（%） = 期間内消費ポイント数 ÷ 期間内発行ポイント数 × 100 |
| 計算例 | 発行：500万ポイント、消費：350万ポイント → 消費率 = 350 ÷ 500 × 100 = 70% |
| データソース | WESTERポイントDBの「point_transactions」テーブル（transaction_type: 'issue' / 'consume', transaction_date） |
| 更新頻度 | 月次（毎月5営業日以内に前月分を確定） |
| 更新タイミング | 翌月5営業日目の午前中 |
| データ欠損の扱い | transaction_typeがNULLのレコードは集計から除外し、件数を別途集計してデータ品質報告に記載する |
| 責任者 | データ分析チーム・〇〇（メール：xxx@xxx.jp） |
| 最終更新日 | 2026年1月15日 |

## 3. モニタリングサイクル

WESTERのKPIモニタリングは、以下の4つの周期で体系的に実施します。

### 3-1. 日次モニタリング（平日毎日・翌朝8時30分までに完了）

**目的**: 前日比での異常値・システム障害の兆候を早期発見する

**確認項目**:

| 項目 | 確認方法 | 異常検知基準 |
|---|---|---|
| WESTERアプリの稼働状況 | システムダッシュボードで確認 | エラー率が0.5%を超えた場合 |
| 当日の新規会員登録数 | 日次集計レポートで確認 | 前週同曜日比50%以下または200%以上 |
| ポイント発行件数・発行数 | 日次集計レポートで確認 | 前週同曜日比30%以下または300%以上 |
| ポイント消費件数・消費数 | 日次集計レポートで確認 | 前週同曜日比30%以下または300%以上 |
| プッシュ通知送達率 | 配信システムのレポートで確認（配信日のみ） | 送達率が90%を下回った場合 |
| お問い合わせ件数 | CSシステムのダッシュボードで確認 | 前週同曜日比200%以上 |

**日次モニタリング実施手順**:
1. 毎朝8時にダッシュボードにアクセスし、各指標の前日値を確認する
2. 異常検知基準に該当する指標がある場合、直ちに担当チームリーダーにSlack/メールで報告する
3. 報告フォーマット：「【日次アラート】〇〇（KPI名）が前週同曜日比〇%（基準:〇%）。調査中。」
4. 異常なし・確認完了の場合もチームチャンネルに「日次モニタリング完了：異常なし」を8時30分までに投稿する

### 3-2. 週次モニタリング（毎週月曜日・正午までに完了）

**目的**: 前週の実績を前週比・前年同週比で分析し、週次トレンドを把握する

**確認項目**:

| カテゴリー | 確認指標 | 集計粒度 |
|---|---|---|
| 会員基盤 | 週間新規会員数・純増会員数・アクティブ会員数 | 週次 |
| 利用頻度 | 週間DAU推移・MAU見込み（週次ペース） | 週次 |
| エンゲージメント | 実施中キャンペーンの参加者数・特典消化数 | 週次 |
| ポイント | 週間発行数・消費数・発行/消費バランス | 週次 |
| CS | 週間問い合わせ件数・主要問い合わせ内容トップ5 | 週次 |

**週次モニタリングレポート提出期限**: 毎週月曜日正午

### 3-3. 月次モニタリング（毎月5営業日以内に完了）

**目的**: 前月の全KPI実績を目標対比で評価し、翌月以降の改善方針を決定する

**確認項目**:

| カテゴリー | 確認指標 | 比較軸 |
|---|---|---|
| 会員基盤 | 月間新規会員数・純増会員数・累計会員数・継続率・チャーン率 | 目標対比・前月比・前年同月比 |
| 利用頻度 | MAU・DAU/MAU・月間アプリ起動回数（平均） | 目標対比・前月比・前年同月比 |
| エンゲージメント | キャンペーン参加率・特典受取率・NPS | 目標対比・前月比・前年同月比 |
| ポイント | 発行数・消費数・消費率・失効数・失効率・残高合計 | 目標対比・前月比・前年同月比 |
| 事業成果 | 施策ROI・乗車促進数 | 目標対比・前月比 |

**月次モニタリングレポート提出期限**: 毎月5営業日以内

### 3-4. 四半期モニタリング（四半期終了後10営業日以内）

**目的**: 四半期単位での目標達成状況・年間計画に対する進捗を評価し、次の四半期の施策方針を決定する

**確認項目**:

| 確認内容 | 詳細 |
|---|---|
| 四半期KPI目標達成率 | 各KPIの四半期目標に対する達成率を算出し、未達の場合は原因分析を実施 |
| 年間目標への進捗 | 年間目標の何%を達成しているか。現状のペースで年間目標を達成できるかを試算 |
| 施策別効果ランキング | 四半期中に実施した施策をROI・KPI貢献度でランキング |
| 課題・リスクの棚卸し | 翌四半期に対処が必要な課題とリスクの一覧 |
| 競合・市場動向 | 交通系・流通系ポイントプログラムの動向と、WESTERへの影響 |

## 4. 異常検知ルール

KPIが通常の範囲から外れた場合、迅速に原因を特定し対応するための基準です。以下のルールを日次・週次・月次モニタリングの中で適用してください。

### 4-1. 閾値設定の考え方

閾値は「前週比」「前月比」「前年比」の3軸で設定します。以下に標準閾値を示しますが、大型キャンペーン実施期間中など、特殊な事情がある場合は事前に閾値を見直してください。

### 4-2. 日次・週次の異常検知閾値

| KPI | 注意レベル（要観察） | 警戒レベル（即日報告必須） | 緊急レベル（即時エスカレーション） |
|---|---|---|---|
| 新規会員登録数 | 前週同曜日比 ±30% | 前週同曜日比 ±50% | 前週同曜日比 ±70% |
| アクティブ会員数 | 前週比 ±5% | 前週比 ±10% | 前週比 ±20% |
| アプリDAU | 前週同曜日比 ±15% | 前週同曜日比 ±25% | 前週同曜日比 ±40% |
| ポイント発行数 | 前週同曜日比 ±20% | 前週同曜日比 ±40% | 前週同曜日比 ±70% |
| ポイント消費数 | 前週同曜日比 ±20% | 前週同曜日比 ±40% | 前週同曜日比 ±70% |
| 問い合わせ件数 | 前週同曜日比 +30% | 前週同曜日比 +50% | 前週同曜日比 +100% |
| システムエラー率 | 0.1% 超 | 0.5% 超 | 1.0% 超 |

### 4-3. 月次の異常検知閾値

| KPI | 注意レベル | 警戒レベル | 緊急レベル |
|---|---|---|---|
| 月間新規会員数 | 目標比 ±10% | 目標比 ±20% | 目標比 ±30% |
| MAU | 前月比 ±5% | 前月比 ±10% | 前月比 ±20% |
| ポイント消費率 | 目標比 ±5pt | 目標比 ±10pt | 目標比 ±20pt |
| チャーン率 | 前月比 +0.5pt | 前月比 +1pt | 前月比 +2pt |
| NPS | 前月比 −5pt | 前月比 −10pt | 前月比 −15pt |

### 4-4. 異常検知時の対応フロー

```
【異常検知時のエスカレーションフロー】

注意レベル：
→ 担当者が当日中に原因仮説を立て、翌営業日の週次報告に記載する

警戒レベル：
→ 担当者が検知後2時間以内にチームリーダーに口頭またはチャットで報告
→ チームリーダーが当日中に原因特定を指示し、24時間以内に上長に報告

緊急レベル：
→ 担当者が検知後30分以内にチームリーダーおよびIT担当に報告
→ チームリーダーが1時間以内に部長に報告
→ システム障害が疑われる場合は、IT部門のインシデント対応フローを起動
→ 会員影響が生じる場合は、コミュニケーション対応（お知らせ・問い合わせ対応強化）を即時準備
```

## 6. 施策効果測定メソッド

### 6-1. A/Bテストの実施手順

A/Bテストは、2つの施策バリアント（A案・B案）をランダムに割り当てた会員グループで比較し、どちらがより効果的かを統計的に検証する手法です。

**A/Bテストの基本手順**:

**Step 1: 仮説の設定**
```
仮説の構造：「〇〇（変数）を変えることで、〇〇（ターゲット会員）の〇〇（KPI）が〇〇（方向性・量）変化する」

例：「プッシュ通知のコピーに乗車回数の具体的な数字を入れることで、
    低頻度会員のプッシュ通知タップ率が現状比+20%向上する」
```

**Step 2: テストグループの設計**
- 対照群（A群）：現状の施策・コンテンツを適用するグループ
- 介入群（B群）：変更を加えた施策・コンテンツを適用するグループ
- グループ分けは必ずランダムサンプリングで行う（担当者の主観でグループを決めない）
- グループの規模は統計的有意性を確保するために「最小サンプルサイズ計算」を実施する

**最小サンプルサイズの目安（簡易計算）**:
```
検出したい効果量（例：5ptの改善）
有意水準：p < 0.05
検出力：80%
→ オンラインのサンプルサイズ計算ツールで算出する（約1,600件/グループが一般的な目安）
```

**Step 3: テスト期間の設定**
- 最低1週間以上（曜日効果の影響を排除するため）
- キャンペーン期間・特殊イベント（連休・大型セール等）と重なる期間を避ける
- テスト開始・終了日時を事前に固定する（途中でのルール変更は禁止）

**Step 4: 結果の評価**
- 主要指標（Primary Metric）の変化を統計的有意性（p値）で評価する
- p < 0.05 の場合、5%有意水準でA/B間に差があると判定する
- 統計的有意差があった場合のみ、B案の採用を推奨する
- サブグループ（会員ステージ別・年齢別等）での効果差も確認する

**Step 5: 意思決定と展開**
- 結果をA/Bテスト結果レポートにまとめ、チームリーダー・上長に共有する
- 採用が決まった場合、展開スケジュールを策定する
- 採用されなかった場合でも、学びをナレッジとして文書化する

### 6-2. 前後比較（Before-After分析）

施策実施前後の同一グループのKPIを比較する最も基本的な効果測定方法です。

**実施手順**:
1. 施策開始の「前期間」と「後期間」を同じ長さで設定する（例：各4週間）
2. 前後のKPI値を比較し、変化量・変化率を算出する
3. 季節性・外部イベントの影響を考慮して解釈する（例：前年同期比も参照）
4. 「施策の効果なのか、外部要因なのか」を必ず検討する

**注意事項**: 前後比較は外部要因の影響を分離できないため、コントロール群（施策適用外のグループ）との比較と組み合わせることを推奨します。

### 6-3. コントロール群の設計

施策の純粋な効果（施策以外の要因の影響を除いた部分）を推定するために、施策を適用しないコントロール群を設けます。

**コントロール群設計の原則**:
- コントロール群は施策グループと同質の特性（利用頻度・年齢分布・居住エリア等）を持つ会員で構成する
- コントロール群の規模は施策グループの20〜50%程度を目安とする
- コントロール群には施策関連の告知・特典を送付しない
- 施策効果 ≒ 施策グループのKPI変化 − コントロール群のKPI変化

## 7. コホート分析の基本手順

コホート分析は、「同じ時期に会員登録した人々（コホート）」の行動を時間軸で追跡することで、会員の定着パターンや離脱タイミングを把握する手法です。

### 7-1. コホートの設定

```
【コホートの定義例】
・月次コホート：「YYYY年MM月に会員登録した会員」を1コホートとして定義
・施策コホート：「〇〇キャンペーン経由で入会した会員」
・属性コホート：「特定の会員ステージに到達した会員」
```

### 7-2. 分析の手順

**Step 1: コホートの抽出**
- 会員DBから対象期間・条件でコホートを抽出する
- 各コホートの会員数を確認する（最低100名以上推奨）

**Step 2: リテンションテーブルの作成**

| コホート（登録月） | 登録時 | 1ヶ月後 | 2ヶ月後 | 3ヶ月後 | 6ヶ月後 | 12ヶ月後 |
|---|---|---|---|---|---|---|
| 2025年1月 | 100% | 〇〇% | 〇〇% | 〇〇% | 〇〇% | 〇〇% |
| 2025年2月 | 100% | 〇〇% | 〇〇% | 〇〇% | 〇〇% | 〇〇% |
| 2025年3月 | 100% | 〇〇% | 〇〇% | 〇〇% | 〇〇% | 〇〇% |

リテンション率 = （N月後もアクティブな会員数） ÷ 登録時会員数 × 100

**Step 3: トレンドの読み取り**
- 特定のコホートで急激なリテンション低下が起きていないか
- 施策実施後に新規登録したコホートの定着率が改善しているか
- 長期的なリテンション率（12ヶ月後）の推移を確認する

**Step 4: 施策との紐づけ**
- リテンション率の変化と、当時実施していた施策・改善施策を照合する
- 「この施策を実施したコホートはリテンションが高い」という仮説を立て、A/Bテストで検証する

## 9. データ解釈の注意点・バイアス排除

正確なデータを集めても、解釈を誤ると間違った意思決定につながります。以下の注意点を常に意識してください。

### 9-1. よくある解釈の誤りとその対処法

**誤り1：相関と因果関係の混同**

「〇〇キャンペーン実施後にMAUが上がったから、キャンペーンの効果だ」と断定するのは誤りです。MAUが上がった原因は、キャンペーン以外（季節効果・天気・祝日・他のサービス変更等）にある可能性があります。

対処法：コントロール群との比較、または同期間の外部要因（天気・イベント等）の確認を行い、因果関係の根拠を示す。

---

**誤り2：サンプルサイズの無視**

小さなサンプルサイズ（例：100件）での効果測定結果を過大評価するのは誤りです。サンプルが少ない場合、偶然の変動が結果に大きく影響します。

対処法：分析結果を報告する際は必ずサンプルサイズを明記する。「n=○○件であるため、解釈には注意が必要」と注釈を加える。

---

**誤り3：平均値の過信**

「平均ポイント保有数が○ポイント」というデータは、一部の高保有者（例：数万ポイント保有）が平均を引き上げている可能性があります。

対処法：平均値だけでなく中央値・分布（ヒストグラム）も確認する。特に分布が偏っている指標では中央値を主要指標として使う。

---

**誤り4：直近バイアス（最近の値を過大評価する）**

「先月のチャーン率が上がったから、すぐに対策が必要だ」という結論を出す前に、それが単月の変動なのか、トレンドなのかを確認する必要があります。

対処法：少なくとも3ヶ月のトレンドと、前年同月を比較してから結論を出す。

---

**誤り5：定義の変更を見逃す**

システム改修・データソースの変更・定義の変更が、KPI値の変化として現れることがあります。「KPIが急上昇した」という場合、まず「定義やデータソースに変更がなかったか」を確認する。

対処法：KPI定義シート（第2章）を常に最新状態に保ち、変更があった場合はレポートに注記する。変更前後の値は不連続になることを明示する。

---

**誤り6：確証バイアス**

「この施策は成功しているはずだ」という先入観を持ったまま分析すると、それを支持するデータだけに目が行き、反証となるデータを見落とす危険があります。

対処法：施策評価を行う際は、「この施策が失敗している証拠はないか」という逆視点でもデータを確認する。可能な限り、施策担当者以外の第三者が効果測定を行う。

---

**誤り7：セグメント分析の省略**

全体のMAUが横ばいでも、ヘビーユーザーが減少し軽度ユーザーが増加していることがあります。全体値だけを見ると重要な変化を見逃します。

対処法：重要KPIは全体値だけでなく、会員ステージ別・年齢別・居住エリア別・入会経路別などのセグメント別にも定期的に確認する。
