# ロジックモデル構築マニュアル（WESTER CS エージェント向け）

> **このマニュアルの目的**
> WESTERにおける施策立案・評価において、ロジックモデルを正確に設計・活用するための実務知識を提供する。新担当者がこのマニュアルだけを読めば、経営層提示レベルのロジックモデルを単独で作成できる水準を目標とする。

---

## 1. ロジックモデルとは（定義・目的・WESTERでの活用場面）

### 1-1. 定義

ロジックモデル（Logic Model）とは、ある施策・プログラムが「なぜ・どのように機能するか」を因果関係の連鎖として視覚化したフレームワークである。投入するリソース（インプット）から始まり、実施する活動（アクティビティ）、生み出す成果物（アウトプット）、利用者・社会にもたらす変化（アウトカム）、最終的な長期的影響（インパクト）へと至る論理的なつながりを一枚の図・表で表現する。

米国のW.K. Kellogg Foundationが普及させたフレームワークで、行政・NPO・民間企業の政策評価で世界標準的に使われている。JR西日本グループにおいては、鉄道利用促進施策・デジタルサービス投資・顧客ロイヤルティプログラム（WESTER）の評価手法として導入が進んでいる。

### 1-2. 目的

ロジックモデルを作成する主な目的は以下の4点である。

| 目的 | 説明 |
|------|------|
| 施策の論理的整合性の確認 | 「この活動をすれば、この成果が出るはず」という因果仮説が正しいか点検できる |
| 関係者間の共通認識の構築 | 企画・営業・IT・経営が同じ図を見て施策の全体像を理解できる |
| KPI設計の基礎づくり | アウトプット・アウトカム・インパクトの各段階に測定指標を割り当てる根拠になる |
| 事後評価の枠組み提供 | 施策終了後に「どの連鎖がうまく機能しなかったか」を特定できる |

### 1-3. WESTERでの活用場面

WESTER施策においてロジックモデルが特に有効な場面を示す。

**（1）新規キャンペーン企画時**
スタンプラリー、ポイントアップキャンペーン、提携サービス連携等を新規立案する際、「誰に・何をして・どんな変化を生むか」を整理する起点として使う。企画書の冒頭に掲載することで、経営層が施策の全体設計を瞬時に把握できる。

**（2）予算申請・稟議書作成時**
投資対効果を示す根拠として、ロジックモデルに沿って「インプット（費用）→ アウトプット（参加数・通知数）→ アウトカム（利用回数増・会員継続率）→ インパクト（収益貢献）」の流れを数値で埋めて提示する。

**（3）施策の中間・事後評価時**
実績値をロジックモデルの各ボックスに記入し、計画との乖離がどの段階で発生したかを診断する。「アウトプットは達成したのにアウトカムに届かなかった」場合、活動⇒アウトカム間の仮説に問題があることが可視化される。

**（4）他部署・外部パートナーとの連携時**
JR西日本グループ内の他事業部門（ホテル・バス・旅行等）や外部パートナー企業（コンビニ、金融機関等）に施策連携を説明する際、ロジックモデルは共通言語として機能する。

## 2. ロジックモデルの5要素

### 2-1. 全体構造図

```
【外部環境・前提条件】
        ↓
インプット → 活動 → アウトプット → アウトカム → インパクト
（リソース）  （実施）  （直接産出物）  （変化・効果）  （長期的影響）
```

各要素は左から右へ因果関係でつながる。矢印は「これがあれば、次が起きる」という論理的前提（IF-THEN関係）を意味する。

---

### 2-2. 要素1：インプット（Inputs）

**定義：** 施策を実施するために投入するすべてのリソース。

**WESTER施策における典型的なインプット：**

| 分類 | 具体例 |
|------|--------|
| 予算 | キャンペーン費用・システム開発費・広告宣伝費・ポイント原資 |
| 人員 | 担当者工数（企画・IT・CS・営業）・外部委託リソース |
| システム | WESTERアプリ基盤・ポイント管理システム・通知配信システム |
| データ | 会員属性データ・行動履歴・過去施策の実績データ |
| パートナーシップ | 提携企業との契約・駅スタッフの協力体制 |
| 時間 | 実施期間・準備期間 |

**記載の注意点：**
- 金額は「総額」ではなく「項目別内訳」で記載する（例：ポイント原資 500万円、システム費 200万円、広告費 150万円）
- 人員は「何人が何時間」という形で工数換算する

---

### 2-3. 要素2：活動（Activities）

**定義：** インプットを使って実際に行う具体的な活動・事業の内容。

**活動は「動詞＋目的語」で記述する。**
良い例：「駅スタンプ設置・管理を行う」「プッシュ通知を3回配信する」「ポイント付与処理を実行する」
悪い例：「スタンプラリーを実施する」（何をするのか具体性がない）

**WESTER施策における典型的な活動：**

| 活動タイプ | 具体例 |
|-----------|--------|
| デジタル配信 | キャンペーンページの公開・プッシュ通知配信・メール配信 |
| リアル施策 | 駅スタッフへの案内周知・ポスター掲示・スタンプ機設置 |
| システム処理 | ポイント自動付与・条件達成判定・特典発送処理 |
| CS対応 | 問い合わせ対応・FAQ更新・エラー対応 |

---

### 2-4. 要素3：アウトプット（Outputs）

**定義：** 活動の直接的な産出物・実施量。活動を「した」ことの証拠。

**アウトプットは必ず数量化できる。**
「誰に何を何回届けたか・作ったか・処理したか」を数値で表す。

| 活動 | 対応するアウトプット |
|------|---------------------|
| プッシュ通知を配信する | 配信数：120万通、開封数：24万通（開封率20%） |
| スタンプ設置・管理 | 設置駅数：50駅、稼働日数：30日間 |
| ポイント付与処理 | ポイント付与件数：8万件、付与総ポイント数：400万pt |
| キャンペーンページ公開 | ページ表示回数：50万PV、登録者数：3万人 |

**重要：アウトプットは「成果」ではなく「実施量」である。**
「会員が満足した」はアウトプットではなくアウトカム。「満足度調査を実施した」がアウトプット。

---

### 2-5. 要素4：アウトカム（Outcomes）

**定義：** 活動の結果として、対象者（会員・利用者）に生じる変化や利益。「施策が目指す本来の目的」に近い概念。

アウトカムは時間軸で3段階に分けるのが一般的である。

#### 短期アウトカム（施策期間中〜終了直後：1〜3ヶ月以内）
- キャンペーン期間中の乗車回数増加
- アプリ起動頻度の上昇
- 参加者のポイント残高増加
- 新規会員のアプリ機能認知率向上

#### 中期アウトカム（3〜12ヶ月後）
- 月間アクティブユーザー数（MAU）の維持・向上
- 会員の交通系サービス以外の利用（ショッピング・旅行等）への波及
- 会員継続率（チャーン率低下）
- 特定路線の利用頻度増加

#### 長期アウトカム（1〜3年後）
- ロイヤル会員比率の向上（ゴールド・プラチナ会員数増）
- WESTER会員のLTV（顧客生涯価値）向上
- JR西日本ブランドへの愛着・信頼度向上
- 非鉄道収益（eコマース・旅行・金融）の増加

---

### 2-6. 要素5：インパクト（Impact）

**定義：** 施策の結果として、中長期的に社会・組織・業界全体に生じる変化。個別施策の成果を超えた、より広い変革。

WESTERにおける典型的なインパクト：

- JR西日本グループ全体の収益改善（交通以外の収益多角化）
- 関西・西日本エリアの移動・生活インフラとしてのポジション確立
- モビリティサービス（MaaS）プラットフォームとしての社会的認知獲得
- 鉄道利用促進による交通CO2排出量削減への貢献（ESG観点）
- 地域経済活性化（観光・商業施設との連携による経済効果）

**注意：** インパクトは1つの施策だけで生まれるものではなく、複数施策の累積効果として現れる。ロジックモデル上ではインパクトを「目指す方向性」として記載し、単一施策での測定は困難であることを明記する。

## 4. 記入手順（ステップバイステップ）

### STEP 1：施策の目的・背景を明確にする（所要時間：30分）

まず、以下の問いに答える。

- この施策は何のために行うのか？（1文で言えるか？）
- 誰が対象か？（ターゲット会員セグメントは？）
- なぜ今やる必要があるのか？（外部環境・競合・社内方針）
- 成功の定義は何か？（3ヶ月後・1年後にどうなっていれば良いか？）

これらへの回答が不明瞭なままロジックモデルを書き始めると、後で大幅な修正が必要になる。

### STEP 2：インパクトから逆算して書く（所要時間：20分）

**右端（インパクト）から左に向かって書く**のが正しい順序である。
多くの担当者がインプットから書き始めて失敗するが、正しい問いは「最終的に何を変えたいのか」から始まる。

1. インパクト：「最終的に何を実現したいか」を1〜2文で書く
2. 長期アウトカム：「インパクトのために、3年後に何が変わっている必要があるか」
3. 中期アウトカム：「長期アウトカムのために、1年後に何が変わっている必要があるか」
4. 短期アウトカム：「中期アウトカムのために、3ヶ月後に何が変わっている必要があるか」
5. アウトプット：「短期アウトカムを生むために、何を何件・何回実施する必要があるか」
6. 活動：「アウトプットを生み出すために、具体的に何をするか」
7. インプット：「活動を実施するために、何がどれだけ必要か」

### STEP 3：前提仮説（IF-THEN）を言語化する（所要時間：30分）

各要素間の矢印（→）が意味する「もし〜すれば〜が起きる」という仮説を明文化する。

例：
- IF 50駅にスタンプを設置すれば、THEN 参加者3万人が複数駅を訪問する
- IF 参加者3万人が複数駅を訪問すれば、THEN 対象路線の乗車回数が月あたり9万回増加する
- IF 乗車回数が9万回増加すれば、THEN 1人あたりの月間乗車頻度が+3回向上する

この仮説を書くことで、「どこに論理の飛躍があるか」が明確になる。

### STEP 4：測定指標（KPI）を割り当てる（所要時間：30分）

各アウトカム・アウトプットに対して：
- **指標名**（何を測るか）
- **目標値**（いくつになれば成功か）
- **測定方法**（どのシステム・データで取得するか）
- **測定タイミング**（いつ測るか）

を記入する。指標は「定量的に測定できるもの」に限定する。「会員満足度が高まる」ではなく「アプリ評価スコアが4.2以上になる」と書く。

### STEP 5：外部要因・リスクを記入する（所要時間：20分）

施策の成否に影響する外部要因を洗い出す。

- 競合サービス（他社ポイントプログラム）の動向
- 季節・天候（特に旅行・イベント系施策）
- 経済環境（物価上昇による可処分所得の変化）
- システム安定性（WESTERアプリの可用性）
- パートナー企業の協力度合い

### STEP 6：関係者レビューを実施する（所要時間：60〜90分）

作成したロジックモデルを以下の観点でレビューしてもらう。

| レビュー担当者 | 確認観点 |
|---------------|---------|
| IT担当者 | アウトプットの数値（配信数・処理件数）の実現可能性 |
| 営業担当者 | アウトカムの市場適合性・競合との差異化 |
| 財務担当者 | インプット（費用）の正確性・ROI計算の妥当性 |
| CS担当者 | 会員の反応・問い合わせ想定 |
| 直属上長 | 全体の論理的整合性・経営目標との整合 |

### STEP 7：最終確認チェックリスト

- [ ] すべての要素が埋まっているか
- [ ] 各要素間に論理的なつながり（因果関係）があるか
- [ ] アウトプットは数量化されているか
- [ ] KPIに目標値が設定されているか
- [ ] 測定方法が具体的に記載されているか
- [ ] 前提仮説（IF-THEN）が明文化されているか
- [ ] A4一枚または見開き2ページに収まるか（経営層提示用）
- [ ] 外部要因・リスクが記載されているか

## 5. 良いロジックモデルの条件（SMART基準等）

### 5-1. SMART基準の適用

ロジックモデルのKPI・アウトカムがSMART基準を満たしているか確認する。

| 基準 | 意味 | WESTERでの適用例 |
|------|------|-----------------|
| **S**pecific（具体的） | 誰が見ても同じ解釈ができる | 「利用促進」ではなく「対象路線の月間乗車回数20%増加」 |
| **M**easurable（測定可能） | 数値で測定できる | 「ブランド向上」ではなく「アプリストア評価4.0以上」 |
| **A**chievable（達成可能） | 現実的な目標値 | 過去施策の実績値+10〜20%が目安 |
| **R**elevant（関連性） | 経営目標と連動している | WESTER年次KPIツリーのどの指標に対応するか明示 |
| **T**ime-bound（期限明確） | 測定時期が決まっている | 「施策終了3ヶ月後」「翌年3月末時点」等 |

### 5-2. 良いロジックモデルの9条件

1. **因果の方向性が一方向に流れる**：左→右に明確な流れがある。循環参照や逆向きの因果がない。

2. **アウトプットとアウトカムが混在していない**：「何を実施したか」（アウトプット）と「何が変わったか」（アウトカム）が明確に分離されている。

3. **インプットがすべて活動につながっている**：記載したリソースが、具体的にどの活動に使われるか対応関係がある。使われないリソースが記載されていない。

4. **アウトカムが施策の対象者（会員）の変化として書かれている**：「WESTERが配信数を増やす」ではなく「会員がアプリを週3回以上起動する」という形。

5. **インパクトが施策単体の成果を超えている**：インパクトは組織・社会への長期的変化。1つの施策で直接達成できるものではない。

6. **前提仮説が検証可能である**：「〜であれば〜が起きる」という仮説が、データや過去事例で検証できる。根拠のない楽観的仮説になっていない。

7. **外部環境要因が明記されている**：施策の成否を左右する外部要因（季節・競合・経済等）がリスクとして記載されている。

8. **測定方法が具体的である**：「調査で確認」ではなく「WESTERポータル管理画面の乗車回数データを施策終了1ヶ月後に抽出する」という水準で記載されている。

9. **A4一枚に収まる簡潔さがある**：情報が多すぎて読みにくいロジックモデルは実務で使われない。詳細は別紙とし、ロジックモデル自体はサマリーとして機能させる。

### 5-3. 良くないロジックモデルのパターン

| パターン | 具体的な問題 |
|---------|------------|
| インプット過多型 | 詳細な費用明細をすべて記入し、全体像が見えない |
| アウトカム不在型 | アウトプットで終わっており、会員への変化が書かれていない |
| インパクト誇大型 | 単一施策で「日本の鉄道文化を変える」等のスケールを書いている |
| KPI未設定型 | 図は美しいが、何も測定しない（評価できない）施策になっている |
| 仮説未言語化型 | 矢印は引いてあるが、なぜつながるのかの根拠がない |

## 6. WESTERの実例（スタンプラリー施策のロジックモデル例）

### 6-1. 施策概要

**施策名：** WESTER夏の関西スタンプラリー2024
**実施期間：** 2024年7月20日〜8月31日（43日間）
**対象：** WESTERアプリ会員（全会員向け、特にライトユーザー活性化）
**目的：** 夏休み期間の関西エリア路線利用促進と、ライトユーザーのアプリ定着

---

### 6-2. 外部環境・前提条件

- 夏休み期間（7〜8月）は家族旅行・友人旅行の需要が高い
- 競合：阪急・南海等も同時期にスタンプラリーを実施予定
- WESTERアプリの月間アクティブ率は全会員の約35%（施策前実績）

## 7. よくある設計ミスとその修正例

### ミス1：アウトプットとアウトカムの混同

**NG例：**
アウトプット欄に「参加者の満足度が向上した」と記載する。

**修正例：**
- アウトプット：「満足度調査を参加者3万人に実施し、3,000件の回答を回収した」
- アウトカム：「参加者満足度スコアが4.2/5.0以上を達成した」

**理由：** 「満足度が向上した」は会員側の変化であり、アウトカム。アウトプットは「何を実施したか」の産出物。

---

### ミス2：インプットに「やる気」「ノウハウ」を記載する

**NG例：**
インプット欄に「担当者の熱意」「チームワーク」を記載する。

**修正例：**
「担当者4名（延べ工数800時間）」「過去3年間のスタンプラリー実績データ」

**理由：** ロジックモデルは客観的に評価可能なリソースのみ記載する。定性的・主観的な要素は測定できないため不適切。

---

### ミス3：活動が抽象的すぎる

**NG例：**
活動欄に「キャンペーンを盛り上げる」と記載する。

**修正例：**
「SNS（Twitter/Instagram）で1日2回投稿し、計86投稿を実施する」
「アプリ内バナーを会員トップページに30日間掲載する」

**理由：** 活動は「誰が・何を・いつ・何回・どのように」が分かる具体的な動詞句で書く。

---

### ミス4：因果関係の飛躍（論理の欠如）

**NG例：**
「プッシュ通知を配信する → 売上が30%増加する」（活動から長期アウトカムに直接つなぐ）

**修正例：**
プッシュ通知配信 → 開封・登録（アウトプット） → キャンペーン参加・乗車（短期アウトカム） → 利用習慣化（中期アウトカム） → LTV増加（長期アウトカム） → 収益増（インパクト）

**理由：** 因果連鎖を省略すると、施策失敗時の原因特定ができなくなる。

---

### ミス5：インパクトが社内目標になっている

**NG例：**
インパクト欄に「WESTERアプリが業界No.1のダウンロード数を達成する」と記載する。

**修正例：**
「西日本在住者が鉄道を主要移動手段として選択するデジタルインフラの確立により、都市部の自動車依存度を低減させる」

**理由：** インパクトは社会・利用者への長期的変化。自社の競争優位や数字目標ではない。

---

### ミス6：KPIが測定方法不明

**NG例：**
KPI欄に「会員満足度：80%以上」と書くが、測定方法欄が空白。

**修正例：**
測定方法：「施策終了翌月に、参加会員に対してWESTERアプリ内ポップアップ調査（5段階評価×3問）を実施し、評価4〜5を「満足」とカウント。母数は調査回答者数とする」

**理由：** 測定方法が不明なKPIは机上の空論。事後評価で「測定できなかった」となる。

---

### ミス7：インプットに施策と無関係な費用を含める

**NG例：**
インプット欄にWESTERアプリの年間システム保守費用（固定費）全額を計上する。

**修正例：**
当該施策のために追加で発生する費用のみ計上する。スタンプ機能の開発費・施策期間中の追加運用費など、施策に紐づく変動費を正確に記載する。

**理由：** 固定費を含めるとROI計算が歪み、投資対効果の評価が不正確になる。

## 8. 経営層への説明時の使い方

### 8-1. 経営層が求める情報の整理

経営層（部長・事業部長・役員）がロジックモデルを見たとき、最初に確認するポイントは以下の通りである。

1. **「なぜこれをやるのか」（目的・インパクト）** → 右端から見る
2. **「いくらかかるのか」（インプット）** → 左端を見る
3. **「本当に効果があるのか」（仮説の妥当性）** → 矢印の根拠を確認する
4. **「どうやって測るのか」（KPI・測定方法）** → KPI表を確認する
5. **「リスクは何か」（外部要因）** → リスク欄を確認する

### 8-2. 経営層向け説明の進め方

**推奨する説明順序（結論先行BLUF方式）：**

1. **結論（インパクト・目的）を先に言う**
   「本施策は、ライトユーザー3万人の乗車習慣を変えることで、施策終了後12ヶ月で約9,000万円のLTV増加を見込みます」

2. **施策全体のロジックを30秒で説明する**
   「このロジックモデルをご覧ください。左のインプット1,800万円から始まり、スタンプラリー実施により、右端のLTV増加9,000万円につながります。ROIは5倍です」

3. **最も不確実な仮説（リスク）を正直に説明する**
   「最大のリスクは、仮説4番の『習慣化』です。施策終了後のMAU維持率が60%を下回った場合、中期アウトカムの達成が困難になります。その際の対応策もご説明します」

4. **承認依頼を明確にする**
   「以上より、本施策の実施承認および予算1,800万円のご承認をお願いします」

### 8-3. 経営層用要約版（1スライド版）の作り方

フルのロジックモデル表は詳細資料として別紙とし、経営層提示スライドには以下の要素に絞る。

```

```

## 9. KPIとの連動方法（ロジックモデル × KPIツリーの統合）

### 9-1. ロジックモデルとKPIツリーの関係

KPIツリーは「目標数値をどの指標に分解するか」を示す構造、ロジックモデルは「なぜその指標が達成できると考えるか」の因果仮説を示す構造である。両者は補完関係にある。

```
【KPIツリー】（何を達成するか・数値の分解）
  WESTER年間LTV目標 ←分解→ 乗車頻度 × 客単価 × 継続率

【ロジックモデル】（なぜ達成できるか・因果仮説）
  スタンプラリー → 乗車回数+25% → 習慣化 → 乗車頻度UP → LTV貢献
```

### 9-2. 統合フレームワーク

WESTER施策のロジックモデルを設計する際、以下の「3層KPI統合マップ」を使う。

**第1層：WESTER全体KPI（事業部ゴール）**
- 会員数（有効会員数・アクティブ会員数）
- 年間LTV（会員1人あたり年間収益）
- アプリMAU・DAU
- ポイント利用率

**第2層：施策別KPI（個別施策ゴール）**
- 各施策のアウトカムKPI（スタンプラリー：乗車増加率・参加者数）
- これらが第1層のどのKPIに貢献するかを明示する

**第3層：アクティビティKPI（実施管理指標）**
- 配信数・開封率・登録率・コンプリート率
- これらが第2層のKPIを達成するための先行指標

### 9-3. ロジックモデル × KPIツリー統合の実務手順

**手順1：**
WESTERの年次KPIツリーを確認し、当該施策が貢献する第1層KPIを特定する。（例：「MAU増加」「乗車頻度向上によるLTV貢献」）

**手順2：**
ロジックモデルのアウトカム欄に、第1層KPIとの対応関係を明記する。
例：「中期アウトカム：参加者のMAU維持率60%以上（→第1層KPI：WESTERアプリMAU目標の+2万人に貢献）」

**手順3：**
KPI達成のための貢献度計算式を作成する。
例：
```
[施策貢献計算]
スタンプラリー参加者3万人 × MAU維持率60% = 継続MAU 1.8万人
WESTERのMAU年次目標増加数 10万人のうち18%を本施策が担う
```

**手順4：**
月次レポート・四半期レビューで、ロジックモデルとKPIツリーの両方を更新する。計画値と実績値の乖離を両フレームワークで確認することで、「数値目標の達成状況」（KPIツリー）と「なぜ達成・未達成なのか」（ロジックモデル）を同時に把握できる。
